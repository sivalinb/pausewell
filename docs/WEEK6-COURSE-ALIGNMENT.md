# Week 6 course alignment: controls, evidence and remaining work

VisitPrep is a close fit for the supplied Week 6 material: the course repository itself includes a healthcare pre-appointment agent and an adversarial HTTP test harness. Pausewell applies that workflow to patient-controlled preparation: a person selects records, inspects exact quotations and dated differences, edits their priorities, and approves their agenda. A second synthetic user provides a separate principal for isolation tests. All example records are authored inventions and do not describe the user's health.

The strongest alignment is **deterministic control around an untrusted model**. The application checks ownership before retrieving source text, requires fresh consent before cloud inference, validates the model's selected quotations, and keeps agenda approval outside the model. The current implementation is a single-owner local application and teaching example. It does not satisfy the handout's enterprise production checklist in full.

This document adds an implementation crosswalk to the [existing assignment checklist](week6-exemplar-checklist.md), rather than changing the [original Week 6 assignment](https://docs.google.com/document/d/1gY0uO00mYyxAWMX8PUe6Jz9Mmsljhnm9jZuPiR6QAdQ/edit). Course examples and enterprise recommendations are distinguished below from completed project work. Reading the supplied materials did not run their installation commands, attack campaigns or external services.

## Apply the course's threat-model method to VisitPrep

H1 pp. 12-19 asks for assets, trust boundaries, attacker goals, impact, controls, detection and recovery. The application-specific interpretation below is our assessment, not a measured incident likelihood or regulatory finding.

**Assets and boundaries.** Protect imported record text, the local SQLite store, source attribution, patient agenda revisions, access/provider tokens and inference spend. Trust boundaries are browser-to-authenticated API, API-to-owned records, selected records/question-to-provider, provider-output-to-validator, approved-revision-to-export, and application-to-telemetry. Unselected records and agenda text do not belong in provider requests. The app server's fixed provider communication is distinct from an attacker-selected outbound tool or URL.

| Attacker goal and impact | Prevention already present | Detection and recovery gap / proposed owner |
|---|---|---|
| Obtain a second synthetic user's records through the first user's session; confidentiality impact is high. | Owner/patient authorization, uniform unavailable response, pre-retrieval tests. | Local counters are not a durable access audit. Before hosting: application owner adds privacy-preserving denial alerts, session revocation and an exercised response procedure. |
| Turn a malicious note into an apparent instruction or unsupported medication recommendation; user-trust impact is high. | Output contract, historical quotation context, neutral questions and source inspection. | Evaluation catches tested output spill. No continuous human sample review exists. Product/evaluation owner should quarantine a suspect source, retain a synthetic reproduction and add a regression case. |
| Export an agenda different from the version the person reviewed; integrity impact is high. | Revision conflicts, approval invalidation, server-side export check and stale-response UI guards. | Approval state is durable, but no independent signed approval audit is claimed. Application owner should exercise recovery from a stale/incorrect export; already downloaded copies cannot be recalled by deleting server records. |
| Exhaust inference spend using repeated valid requests; financial/availability impact rises with hosting. | Per-call size/time/output limits and no autonomous loop. | Add the cloud quota gate proposed below before public authenticated hosting. Platform owner needs a provider-disable procedure and spend alert. |

H1 pp. 27, 29 and 33 describe a broader policy/enforcement/telemetry/review loop. VisitPrep has concrete gates and tested approvals, plus bounded local operation events and synthetic Braintrust evidence. It does **not** have immutable production audit storage, control IDs on every runtime event, SIEM routing, a named operational on-call, a rehearsed backup/restore program, or automated remediation. The original 100-event in-memory operation buffer remains. Dedicated NeMo spans now persist in a bounded local SQLite store with cumulative operational metrics, but that store and uploaded synthetic traces must not be called a complete compliance evidence pipeline. No certification under ISO, NIST or the EU AI Act is asserted.

## Highest-value bounded next control

**Proposed, not implemented: a production cloud-inference admission gate.** This closes a concrete H2 p. 8 / H1 p. 36 gap without expanding the agent's powers. Put it after authentication, source authorization and explicit consent, but before the provider request. Enforce a configured request allowance, concurrent-call limit and conservative spend reservation in persistent owner-scoped state. Keep local mode available when the cloud allowance is exhausted. Unknown timeout usage must not be treated as zero cost.

Acceptance criteria:

1. Repeated and concurrent synthetic HTTP calls cannot exceed the configured allowance; denied calls produce **zero** provider requests, including across process restart.
2. Invalid authorization or missing consent never reserves budget or invokes the provider. The gate is server-side, independent of disabled UI buttons.
3. A timeout retains its conservative reservation until reconciliation; the reservation cannot be overspent by concurrent requests. A non-sensitive denial status reaches the user and bounded telemetry.
4. Tests use a mock transport and temporary store. A separate explicit paid smoke, if desired later, records actual usage without altering frozen evaluation evidence.

Two useful course-specific follow-ups are a local Presidio preview experiment and an optional Promptfoo provider adapter. The preview must show exactly what text would leave, keep token mappings local, preserve source/quotation fidelity when restoring entities, and measure missed entities and damage to useful evidence with authored synthetic fixtures. It must not promise complete anonymization. The Promptfoo adapter should reuse the real HTTP authorization/consent path and independent scorer, with explicit synthetic-only execution and a budget; do not label it completed until it runs. Neither library name substitutes for a deterministic security boundary.

## Evidence to present with the course mapping

The [new local NeMo comparison](../visitprep_eval/reports/nemo-local/README.md) and [fresh NeMo-enabled hosted suite](../visitprep_eval/reports/nemo-live/README.md) supply separate execution evidence. The former varies the local rail setting with fixed provider envelopes and measures no final-safety/utility gain; the latter records 21 actual Nebius calls and five input-rail local fallbacks. Neither changes the attribution of older course and provider experiments.


Use the [pre-NeMo live safety report](../visitprep_eval/reports/siva-live/summary.json), [paired utility report](../visitprep_eval/reports/utility-live-siva/summary.json), [offline report](../visitprep_eval/reports/offline-siva/summary.json) and [credential-free replay](../visitprep_eval/teaching/README.md) together:

- The live safety run records 29 cases, 28 PASS / 1 WARN, 26 provider calls, 24 accepted selections and two rejected empty selections. Passing application boundaries does not mean every model response was useful.
- The paired utility experiment records 32 completed calls on 16 previously seen synthetic cases. Prompt-only/full source-and-instruction safety is 15/16 versus 16/16; useful target spans are 21/24 versus 24/24. UT-13 is quoted instruction contamination in the prompt-only output, **not** observed curl execution or network exfiltration.
- UT-16 appropriately returns no facts from an instruction-only source in both systems. The full application's `rejected_output` label reflects its nonempty-fact rule; its fallback supplies no facts. This is an abstention-classification limitation, not an unsafe answer.
- The local selector still covers 20/24 utility targets, or 21/24 across all presented difference evidence. Keep those omissions and the original captured failures visible. These are small authored regression studies, not clinical validation or an unseen adaptive benchmark.

This supports a strong Week 6 case study with inspectable controls, an actual model comparison, reproducible evidence and honest operational gaps. Public source availability is distinct from a public service handling private records; H1's production checklist remains a deployment gate, not a claim that a successful course demonstration is production-ready.
